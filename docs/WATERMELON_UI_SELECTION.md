# Watermelon UI selection for DCMUN

Research and owner-brief addition, 19 October 2026.

## Decision

Select a small set of Watermelon patterns for DCMUN's existing **Assembly** identity: **Skeleton**, **Spinner**, **Combobox 1**, a simplified **Continuous Tabs** active indicator and **Copy Confirm** feedback. Use **Gridline**, **Agndex** and **Tallie** as targeted composition references. Add genuine, stable loading states; preserve the durable-save contract and the fixed sync strip.

This is a shortlist for Claude, not approval to import an entire dashboard, change the application's permissions or replace the current shell. Keep the DCMUN seal, Manrope/DM Sans, existing colour tokens and 48 px Launcher Felix.

## What was checked

Reviewed Watermelon's public gallery, documentation and source snapshot `8c969e108650256cbc12ee9473a6fce78ba6e3ad`. Its source tree contains one full landing template, 12 dashboard metadata entries and 131 animated-component metadata entries. I inspected the published Landing Page 01, Tallie, Gridline and Agndex previews, read six dashboard metadata entries, inspected the selected component sources/base variants and supporting primitives, and checked the target MUNOS dependency manifest at reviewed commit `0a43c73`.

The HTTP catalog API was unavailable from this environment. Source inspection used the official public GitHub repository instead; no account or installation was needed. Some public detail pages were also unavailable to the text browser, while the browser preview and repository were usable. The findings below distinguish source review from demonstrated production performance. No imported-component benchmark in MUNOS has been run.

## Loading states to add

| Situation | Intended UI | Truth and layout rules |
|---|---|---|
| Access is being checked | Compact “Opening your workspace…” state using the brand and a small indicator | Do not reveal unauthorised role cards or sensitive fake workspace content while checking access. No fixed startup delay. |
| First uncached screen read | Header/navigation remain stable; a few row-shaped skeletons occupy the final content positions | Never show “No resolutions” or “All changes synced” before the relevant successful read. Skeletons are decorative and the containing region has an appropriate busy state. |
| Cached data exists and a refresh is pending | Keep useful saved data and scroll/focus in place; update the persistent sync strip | No full-screen loader, content blanking or skeleton flash. Preserve the reviewed failed-read/stale-data wording. |
| Saving an entry locally | The relevant button may show an inline pending indicator until the durable local write resolves | After local commit, say saved on this device and keep the normal outbox workflow. Do not hold the debate hostage to network confirmation or auto-close the form on a failed save. |
| Reading/verifying a Google Doc | Inline “Checking document access…” beside the link/action, with reserved space | Verification success comes from a real supported check. Failure or inability to verify keeps the link and gives an actionable result. No animated percentage. |
| Typing in the country picker | Immediate local result filtering | No artificial spinner or input delay for a small local list. Keep query, highlight and selected item stable. |
| A genuine measured import/procedure step | Short labels and an optional determinate indicator if actual progress is known | Progress must come from real counts or operation state. Never animate a guessed percentage or rotate made-up stages. |
| Request fails or takes unusually long | Retain usable cached content/entered values; show a specific retry/details path | A perpetual spinner cannot substitute for error handling. Retrying must preserve the existing idempotency and access rules. |

Indicators may appear after a short pending threshold to avoid flashing for near-instant operations, but must never impose a minimum wait or delay an actual result. Prefer three calm skeleton rows to a whole screen of moving placeholders. Stop repeated animation in background/offscreen regions and provide a static reduced-motion version.

The global status strip is always present below navigation in its reserved-height slot. Status changes can fade text within that slot, but neither its height nor the content position changes. A spinner is a busy indicator, not proof that an action is persisted or acknowledged.

## Attractive demos that should not be copied into critical workflows

- **[Run Action Button](https://ui.watermelon.sh/animated-components/run-action-button):** the reviewed source advances stages every 1.2 seconds and sets itself to done. It also changes width and animates per-letter blur. Reject it for saving, syncing, submitting and approval. A real action-state contract would need to replace that behaviour completely. [Source](https://github.com/WatermelonCorp/watermelon-platform/blob/8c969e108650256cbc12ee9473a6fce78ba6e3ad/src/data/contents/animated-components/run-action-button/original.tsx)
- **[Labeled Progress Indicator](https://ui.watermelon.sh/animated-components/labeled-progress-indicator):** the demo defaults to 55 percent, cycles its labels on a timer and repeats a shimmer. Reject it as a network/sync progress display. Use plain actual status text instead. [Source](https://github.com/WatermelonCorp/watermelon-platform/blob/8c969e108650256cbc12ee9473a6fce78ba6e3ad/src/data/contents/animated-components/labeled-progress-indicator/original.tsx)
- **[Command Search](https://ui.watermelon.sh/animated-components/command-search):** useful as a broad inspiration but not the speech/POI picker. The reviewed source expands to a 320 px-high palette, adds a backdrop, captures a global F shortcut, uses substring rather than the required fuzzy ranking and needs no-results keyboard hardening. The compact Combobox is a better starting point. [Source](https://github.com/WatermelonCorp/watermelon-platform/blob/8c969e108650256cbc12ee9473a6fce78ba6e3ad/src/data/contents/animated-components/command-search/original.tsx)
- **[Inline Toast](https://ui.watermelon.sh/animated-components/inline-toast):** do not replace the persistent sync strip or the in-dialog save error with a timed, morphing toast. [Source](https://github.com/WatermelonCorp/watermelon-platform/blob/8c969e108650256cbc12ee9473a6fce78ba6e3ad/src/data/contents/animated-components/inline-toast/original.tsx)
- **Discrete Tabs, Dropdown Disclosure, Event Reminders and Quick Switcher:** source-reviewed but not selected for copying. Their expanding layouts, extra icons, measurements or widget-specific behaviour add less than a simple existing primitive for this scope. Keep the authoritative photo schedule and reviewed notification rules rather than importing a demo scheduler.
- Shimmer buttons, gooey menus, carousels, animated counters, background particles, big reveal effects and springy data-row reordering are not needed on the live debate interface.

## Source review requirements before integration

The target manifest at `0a43c73` contains no Motion, Tailwind, cmdk, Base UI, Radix, Recharts, Hugeicons or dnd-kit dependency. Watermelon source uses Tailwind classes and project-local aliases. **Do not paste it in and assume it is styled or accessible.** Port useful presentation into `docs/BRAND.md` tokens and the current primitives; measure any new dependency separately. Do not transplant Vite routing or theme providers into Next.js.

Static issues found in the examples include missing reduced-motion branches; Continuous Tabs removes outlines without a visible focus replacement on the buttons, uses broad transition/layout behaviour and initially returns null until mounted; Copy Confirm lacks clipboard-failure handling and imports legacy `framer-motion`; several demos contain timer-driven fake data/progress or large full-height wrappers. These are integration fixes, not reasons to claim the whole library is unsafe. Watermelon's “production ready” description is not DCMUN's accessibility or reliability verification.

For navigation, use real links and current active-route state. For content tabs, retain tab semantics, keyboard behaviour and focus. For popovers/dialogs, preserve accessible names, Escape and focus restoration. Test country selection with Enter, composition input and no results. Keep source timers cleaned up and avoid state changes after unmount.

## Performance and acceptance gates

- Default transitions: 120–180 ms, opacity/transform only; interactions stay available immediately. The Felix petting sequence remains its separate bounded design.
- Do not animate table sort order, live point updates, the page shell height or every passive refresh. Avoid backdrop blur and per-letter effects in working screens.
- Compare the production client bundle before/after each dependency addition. Record the actual increase; no unmeasured “zero cost” claim.
- Check a representative Chair laptop, phone width and reduced motion, with a full DCMUN-sized local dataset. Confirm country filtering stays under the proposed 50 ms target with no new long task attributable to the selector; judge transitions using actual interaction traces.
- Repeated initial-read, cached-refresh, save, send, confirmation, offline, failed-read and conflict transitions must not change the first content panel's vertical position. Target zero status-induced layout shift.
- Check keyboard-only, touch and 200 percent zoom; no clipped popover or action button. Loading announcements must be meaningful without repeating every timer tick.
- Run the relevant regression tests, typecheck, lint and build when integrated, then real authenticated flows on staging. This research is not a bundle benchmark, deployed import or replacement for the conference-week capacity rehearsal.

## Claude implementation order

1. Add stable loading primitives and consolidate the reserved-height sync strip, preserving truthful repository states.
2. Implement the compact country combobox and clipboard confirmation using current design tokens and the existing event/outbox contract.
3. Apply Gridline-inspired compact workspace cards, Agndex-inspired rows and Tallie-inspired optional history detail within Assembly.
4. Add the small active-tab and popover/dialog transitions after the baseline interaction checks pass. Choose CSS/WAAPI first; use one Motion package only if it supplies measurable value.
5. Update `docs/UI_OVERHAUL.md`, `docs/BRAND.md` and the todo list with selected references, intentional omissions, tests and remaining constraints.
